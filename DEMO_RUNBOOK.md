# Three-minute native research walkthrough

Launch `./open_3d_demo.sh`. Keep the default full cloth view; **X cutaway must read OFF**. Press Space to pause, then R to reset. The entire initial sheet must be visible above the sphere. F reframes the current geometry if the camera has been moved.

1. Press 1, then Space. Explain the falling cloth and fixed obstacle. These positions are integrated by the C++ solver in the running application, rather than read from an animation file. Pause while the cloth is draping and press F.
2. Press 2. Explain one format: stable primitive ID, geometric min/max bounds, category/mask and movable flag. The request supplies the proximity margin and update policy. The displayed certified bounds enclose the currently padded geometry; the view caps triangle-box overlays at 40 for readability, while all primitives remain in the query.
3. Press 3, then 4. Amber triangles are retained candidates; green triangles pass the precise sphere–triangle distance test. Extra broad-phase candidates are expected. Candidate and proximity views show the complete cloth unless X is explicitly enabled.
4. Press Q until the panel reads REBUILD EVERY ITERATION, then N. Observe the build counter for that physics step. Press Q to GUARDED ENVELOPE REUSE and N again. The service keeps actual candidate pairs while every padded bound stays inside its certified envelope. It rebuilds on an escaped envelope or incompatible request. This is the before/after mechanism; switching policies does not intentionally change contact physics.
5. Press M, then N. The changed proximity request invalidates the cache. Point out the new margin and the build/reuse counters. B can switch to the exhaustive AABB reference; leave SAP selected for the main demo.
6. **Use the new post-fix chart** generated by `./scripts/prepare_meeting.sh`
   (`output/native/benchmark-postfix.svg`). The original `benchmark.png` is
   historical pre-fix evidence; its timing includes an exhaustive per-iteration
   oracle and must not be described as current post-fix speedup.
   Five paired trials, identical inputs and settings, mean / p95 / maximum CPU step time. State that all particle positions matched and no required pairs were omitted in this fixture. Timing includes oracle diagnostics and excludes rendering. This is a local prototype measurement, not a cross-solver benchmark.
7. End with the proposed first real adapter: retain an existing method's narrow phase, solver, tolerances and motion requirements; replace candidate generation alone and compare coverage, outcomes, stage cost and total runtime.

The app writes per-step state and measurements to `ccp-native-lab/native_trace.csv` within the system temporary directory and input events to `native_events.log` alongside it. The app prints the exact runtime folder on startup; `--trace PATH` chooses an explicit trace destination. A measured frame has both a position checksum and oracle count. These logs make live controls inspectable; the stronger paired benchmark compares all particle coordinates, not just checksums.

Press **V** to toggle the independent oracle. With it OFF the panel must read
"ORACLE NOT CHECKED," not "0 misses." With it ON the program checks all
required proximity pairs at each solver iteration. Use ON during the meeting;
leave the benchmark executable to measure with oracle OFF only after a separate
oracle-checked preflight.

The legacy rigid-sphere/browser viewer (`./run_demo.sh`) independently
demonstrates contact islands and swept sphere TOI. It is a **separate** solver
and not part of the native cloth/OGC experiment. Do not conflate them.

Leave collision response ON, cutaway OFF, and margin 0.05. Press R to prepare the next demonstration.

## Island supporting-demo instructions

Use `./scripts/launch_meeting.sh islands` to open the older browser viewer.
Select scene **02 · Contact islands**, reset, start and pause as the moving
groups approach. Candidate lines represent broad-phase possibilities;
confirmed-contact links contribute to the island graph. Distinct group
colors can merge at actual cross-group contact. This is a **separate C++
rigid-sphere impulse solver**, not a hidden island implementation of XPBD cloth.


## New main research demo: the geometry genuinely keeps changing

Run `./open_multicloth_demo.sh`, not the earlier static sphere fixture.
Default is three moving deformable sheets and two moving spheres. The cloths
are physically coupled by experimental discrete inter-sheet feature contact
corrections. Press L for 1/2/3 cloths, Q to compare full SAP versus global
guarded SAP versus local region certification, G for a scrollable live cache
log and continuous candidate/contact time-series, A for exhaustive broad-phase
pair auditing, and 1/2/3/4 for stages. This is an actual simulated scene,
not a prerecorded movie. The exact scope and limitations are in
`docs/MULTICLOTH_CONTRACT.md`.


## Interactive fabric manipulation and self folds

Launch the corrected multi-cloth viewer with ./open_multicloth_demo.sh. Same-cloth collision is enabled. Click and hold the LEFT mouse button on the fabric and drag to move its actual picked surface point; release to let it settle. RIGHT mouse drag or SHIFT+LEFT drag rotates the camera; left-drag on the background also rotates. S toggles same-sheet contacts so you can compare with the previous intersecting state, G opens measured logs, and 4 highlights actual contact-response triangles. The cursor attachment is a smooth mass-weighted constraint, not instantaneous vertex teleportation. Inspect self-contact corrections and discrete geometric piercings in the native sidebar. This is not a guaranteed continuous collision detector; see docs/SELF_COLLISION_AND_DRAGGING.md.
